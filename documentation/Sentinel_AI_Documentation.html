Executive Summary

1. System Overview & The Core Problem

Modern retail banking institutions handle billions of dollars across millions of transactions every day. While the vast majority (98%) are legitimate consumer purchases, a tiny fraction (2%) represent sophisticated criminal activities: account takeover attempts, credential stuffing, card-not-present fraud, and anomalous high-velocity ATM cashouts.

Key Project Objective: Analyze banking transaction behavioral patterns, solve extreme class imbalance without data leakage using SMOTE, compare 4 industry-standard machine learning algorithms, eliminate costly False Negatives (missed theft), and deploy an automated 3-Tier Prevention Engine through a clean minimalist 3D WebGL interface.

Why Simple Models Fail: The Asymmetric Cost of Fraud

In standard machine learning problems, misclassifying Class A as Class B carries equal weight. In banking fraud, the cost is violently asymmetric:

False Negative (FN) = Disaster

The AI marks a stolen transaction as "Legitimate".

  • Direct financial loss for the bank and cardholder.
  • Regulatory penalties & severe reputational damage.
  • Sentinel Result: 0 False Negatives (100% Recall).

False Positive (FP) = Nuisance

The AI marks a good transaction as "Suspicious".

  • Cardholder receives a prompt / SMS OTP (friction).
  • No money is lost; customer verifies with 1 click.
  • Sentinel Result: Only 2 False Positives in 9,800 tests.

System Architecture & Workflow

Figure 1.1: Multi-Model Evaluation Matrix across 5 Key Statistical Dimensions
  1. Data Preprocessing: 50,000 banking transactions with 15 behavioral, temporal, and categorical attributes.
  2. Stratified Split: 80% Training (40,000 rows) / 20% Evaluation Test Set (10,000 rows).
  3. SMOTE Over-sampling: Applied strictly on the training set to prevent synthetic data leakage into test sets.
  4. Model Orchestration: Parallel training of Random Forest, Decision Tree, Support Vector Machine, and Logistic Regression.
  5. Inference Engine & HUD: Real-time probability scoring and 3-Tier prevention routing via Flask REST API and 3D WebGL.

The Accuracy Paradox Explained

Figure 5.2: Exposing the Accuracy Paradox — Why 98% Naive Accuracy Catches Zero Frauds
What is the Accuracy Paradox?
In a dataset where 98% of transactions are legitimate, a "dummy" model that predicts "Legitimate" for every single transaction achieves 98.0% Accuracy without learning anything! However, its Fraud Recall is 0%, meaning every thief succeeds. Sentinel exposes this fallacy by proving that Recall and F1-Score are the true measures of risk intelligence.

Quick Reference

7. Presentation & Interview Q&A Cheatsheet

Use these concise answers when presenting Sentinel AI to examiners, recruiters, or executive panels:

Q1: Why did you choose Random Forest as the champion model?
Answer: Random Forest achieved the highest overall score: 99.98% Accuracy, 100% Recall, and 99.50% F1-score. Crucially, it generated 0 False Negatives (zero missed frauds) and only 2 False Positives across 10,000 test transactions, beating single Decision Trees and Linear models.
Q2: Why is Accuracy an insufficient metric for fraud detection?
Answer: Because of the Accuracy Paradox in imbalanced datasets (98:2). A naive classifier predicting 100% legitimate transactions gets 98% accuracy while missing every single crime. Precision, Recall, F1-Score, and ROC-AUC are mandatory to measure real fraud-catching ability.
Q3: How was data leakage prevented during SMOTE balancing?
Answer: SMOTE was applied strictly after the 80/20 train-test split, only on the training set. The 10,000 test records remained 100% real and untouched, ensuring benchmark integrity.
Q4: How does Sentinel differ from typical ML demo projects?
Answer: Sentinel bridges the gap between machine learning theory and production fintech. Instead of stopping at a prediction percentage, it features an automated 3-Tier Prevention Engine that executes specific business actions (Approve, 2FA Challenge, Freeze) based on risk thresholds and velocity triggers.
Q5: What are the top 3 transaction signals that indicate fraud?
Answer: 1. Internal Risk Score (~50%): Behavioral profile deviation.
2. Failed Login Attempts (~21%): Credential stuffing / password guessing.
3. Transaction Hour (~14%): Uncharacteristic midnight-to-4 AM activity.
